# Codex Workflow

Use the lightest control loop that can produce the requested evidence-backed result.
This plugin provides methods, not repository policy or extra authorization. Current task
instructions and binding project contracts control; explain a real conflict instead of
silently changing the task. Discover local owners rather than importing another project's rules.

Read only the reference that resolves the present decision:

| Decision | Reference |
| --- | --- |
| Bounded result, exploratory campaign, or stable outcome needing coordination? | [Modes](references/modes.md) |
| Substantial design/planning or a handoff to another execution context? | [Planning and deeper checks](references/planning.md) |
| Authorized delegation, registered roles, review or integration? | [Orchestration](references/orchestration.md) |
| Continue, compact or change an expensive working context? | [Context economics](references/context.md) |
| What evidence is enough, what remains valid, and when to stop? | [Evidence and closure](references/evidence.md) |
| An actual model/effort or environment choice? | [Revisable defaults](references/models.md) |

Use the package's `pr-ci`, `test-audit`, `docs-gardening` or `complexity-discipline`
skill for its distinct task when available. Use `codex-workflow-setup` for project integration.
Do not load those skills merely because they exist. A host without repository access can
help plan from supplied evidence, but cannot claim source inspection, checks or mutations.

Conclude with the result, evidence sufficient for the decision, and material remaining gaps.
Do not manufacture a plan, goal, agent topology or review to demonstrate use of the workflow.
