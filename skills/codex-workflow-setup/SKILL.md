# Set up Codex Workflow

Make this project's authorities, evidence routes and operational boundaries usable with the
installed plugin. An invocation authorizes in-scope local instruction integration, not changes
to application behavior, dependencies, CI gates, release/deployment policy, personal settings
or external services. Preserve unrelated work and deliberate local adaptations.

## Discover before adapting

Inspect current project instructions, architecture/contract routes, manifests or task runners,
CI/contribution rules and relevant local skills. Establish what already works. Follow their
referenced owners where needed; a skill file alone may not contain its reusable method.

Identify the few facts needed for actual project work: source precedence, implementation owners,
focused checks and their prerequisites, required hosted/manual evidence, consequential-action
boundaries and unusual risks. Infer routine facts from source; ask about material intent or
authority that source cannot establish. A project without CI or a deployment process does not
need invented policies or infrastructure.

Check whether the plugin and requested runtime capabilities are available. ChatGPT planning,
Codex filesystem work and custom-role dispatch have different tools. If direct project access
is absent, produce a bounded integration proposal from supplied evidence and identify what
still needs local execution. Never claim edits or registration from instructions alone.

## Integrate the minimum

- Adapt the [operating fragment](../../templates/AGENTS-workflow.md) into existing `AGENTS.md`;
  do not replace the whole file or duplicate already-correct sections. Essential scope,
  authorization, evidence and stopping rules must work even without the plugin.
- Route shared methods by skill name, not a machine-specific plugin-cache path. Keep local
  policy and commands at their existing owners. Add a small adapter only if its routing earns
  another file; [the adapter template](../../templates/PROJECT.md) is optional.
- Inspect local skills individually. Extract portable methods upstream only within the authorized
  source scope; otherwise report the candidate. Preserve local gates and procedures, and remove
  an empty wrapper only after repairing its consumers and verifying the shared route is available.
- The [optional role definitions](../../.codex/agents/) are source assets, not automatic runtime
  registrations. Install/reconcile them only when useful and authorized, following the host's
  current registration mechanism. Do not overwrite adapted roles or modify user configuration
  merely because the plugin includes defaults. Report unavailable routes honestly.

For an old copied installation, first preserve unique project guidance in its appropriate owner.
Repair active links and triggers, then retire superseded portable copies within authorized scope.
Do not leave two active workflow editions or delete historical evidence. Existing integration
is a reconciliation input, not permission to reset the repository.

## Verify and finish

Check the changed routes, paths, meaningful trigger boundaries, source precedence and preservation
of mandatory constraints. Run only the relevant project checks; do not run builds or live probes
to validate prose. Rerunning setup should preserve correct adaptations and avoid duplicate sections.

Report files changed, project facts established, unresolved policy/capability gaps, and remaining
manual steps. Updating the plugin changes shared methods; setup changes local integration.
